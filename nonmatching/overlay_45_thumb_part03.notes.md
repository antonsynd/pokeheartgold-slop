# overlay_45_thumb part 03

- ov45_0222A9A0 to ov45_0222AB0C are accessors of the Wi-Fi plaza profile (Platinum's WiFiPlazaProfile). Layout used: +4 trainer id, +0x1C word, +0x38 gender (u8), +0x39 language (u8), +0x3A appearance index (u16), +0x3C country (u16), +0x3E region (u8), +0x41 byte, +0x88 u16[2], +0x8C and +0x90 two words. Same offsets as Platinum.
- ov45_02254A84 is a 16 entry table of {u16 graphics id, u16 gender}. It is defined in this file and the gate confirms it equals the ROM bytes.
- ov45_0222AB1C to ov45_0222AD58 take the plaza work structure (Platinum's UnkStruct_ov66_0222DFF8). Offsets from the asm: +0x1E8 byte array of 0x14, +0x3CC block of 0x14 bytes (Platinum says 0x3CB, the asm is 0x3CC), +0x3E4 block, +0x508 a pointer (trainer info). The 0x14 byte message built by ov45_0222AB94, ov45_0222ABD0, ov45_0222AC14 and ov45_0222ACB8 has four words at +0, then bytes at +0x10, +0x11, +0x12 and a byte at +0x13 holding a 7 bit field (low) and a 1 bit field (bit 7).
- ov45_0222A9CC does not pass the gate, and it cannot. When the gender byte is 2 or more, the appearance lookup does not return 0xFFFF and no table entry's first halfword equals the appearance index, the asm returns r4 unchanged, that is the value the caller left in r4 (the gate starts r4 at 0x40000004). The C leaves `ret` uninitialised on that path as Platinum's twin does. With `ret` initialised to 0x40000004 in a scratch copy of the file, check.py prints PASS on 2000 trials, so every defined path agrees. Note the loop stores the table's graphics id (the compared halfword), not the gender column; that is what the asm does.
- ov45_0222AC14 does not pass the default gate because the symbol table splits one function in two. The function is ov45_0222AC14 to ov45_0222ACB8 (0x2AC14 up to 0x2ACB8): it zero-fills the 0x14 byte message, maps the type with a jump table, and the shared tail at _0222AC5C and _0222ACB4 sits after the table. symbols.json gives ov45_0222AC14 only up to 0x2AC58 and makes the rest a separate "function" ov45_0222AC58, whose first instructions are `add sp, #0x14; pop {r4, r5, pc}` (the epilogue of ov45_0222AC14). The gate therefore sees every path of ov45_0222AC14 end in a call to an address outside the window. ov45_0222AC58 has no C definition because it is a fragment of ov45_0222AC14 and cannot be called on its own. Checked with a scratch copy of symbols.json whose ov45_0222AC14 entry ends at 0x2ACB8 (`check.py ov45_0222AC14 ... --symbols <copy>`): PASS on 2000 trials.
- Platinum's twin for ov45_0222AC58 is really the twin of ov45_0222AC14 (eight parameters, the last stored into bit 7 of the byte at +0x13).
