# overlay_45_thumb part 01

- The first three functions are the Wi-Fi plaza overlay's init, main and exit callbacks (Platinum's ov66_0222DCE0, ov66_0222DD6C and ov66_0222DD90); the others are the accessors of its work structure (Platinum's UnkStruct_ov66_0222DFF8), 0x530 bytes. HeartGold differences from the twin: the init also calls sub_02039FD8(3) before creating the heap, and the overlay it loads is overlay 42 (Platinum: overlay 63).
- The overlay id is written as the literal 42. `FS_OVERLAY_ID(OVY_42)` would reference SDK_OVERLAY_OVY_42_ID, which has no address in symbols.json, so the gate stops with "no address for SDK_OVERLAY_OVY_42_ID".
- The twin tool's renamed calls are wrong in several places (it maps HeartGold's sub_020318E8, sub_020318FC and sub_02031900 to unrelated Platinum names, and its ov45_0222C36C and ov45_0222C8AC offsets are off by one); the asm gives ov45_0222C3B0 at +0x20C and ov45_0222C8AC at +0x3AC.
- Layout used for the work structure: +0 save data, +4 and +8 the sub state (pointer and a word compared to 1), +0xC copy target of ov45_0222B79C, +0xD4 a block with a 64 bit time stored at +0xD8, +0xE8 four player profiles, +0xF8 to +0x104 four event bit masks, +0x108 the profile block (its profile at +0x20 of it), +0x1C0, +0x1E8, +0x1FC a 0x10 byte state block with a flag byte (bit 0, bit 1, bits 2-3, bit 4, bits 5-6, bit 7), s16 timers at +4, +6, +8 and +0xA, and two nibbles at +0xF; +0x20C, +0x3A0, +0x3AC, +0x3CC, +0x3E4, +0x49C, +0x4BC, +0x508 sub blocks, +0x528 heap id, +0x52C a done flag.
