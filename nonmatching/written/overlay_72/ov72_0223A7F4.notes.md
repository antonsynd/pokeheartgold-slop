The asm writes `digits[(s16)p[4]] = val` with no bounds check, into a stack array at entry_sp - 0x20.
For the check's random s16 index that write lands outside the frame, so the C reproduces the store
address from the entry stack pointer (frame address + 8 under clang's frame-pointer prologue).
Indices 3..8 would hit the original's saved registers and are not modelled (the game never passes them).
