# ov112_021E6164 - gave up (sandbox artifact)

The C in ov112_021E6164.c is a faithful reading of the asm, but the check cannot pass it.

The asm's bounds check for the state switch on `ov112_021FFB24[0x1D]` (values 0x46..0x4C) uses
`bl _021E6A50` as a far branch to the function's own epilogue (`pop {r3-r7, pc}`). On hardware that
simply returns from the function. The sandbox instead records it as a call to 0x021E6A50, stubs it
with a pseudo-random r0, and then continues into the jump table with that r0 as the index, so the
original side goes on to run one of the cases (or jumps wildly). The C correctly returns, so every
trial where the state byte is outside 0x46..0x4C reports "the number of calls differs".

Reproducing the sandbox behaviour would require calling into the middle of the original function,
which would not be correct on hardware, so this was left as is.

Also note: `_ll_udiv`, `_f_ulltof` and `_fdiv` (the elapsed-time computation, whose result is unused)
are called explicitly so the helper sequence matches.
