# sub_02011F10

The C follows the asm: the sine product, the angle chain (`_s32_div_f` for both divisions and the signed
halving), the call to sub_02010A54 (>> 12) and sub_02010A00, then the 96-step loop that stores two s16 rows
at v9+0x300 and v9+0x480 (forwards and mirrored at 191-i).

v3 is a 192-entry stack table, and the original indexes it with `v1 - (i + 1)` where v1 is the
sub_02010A54 answer (>> 12). The asm only logs for v1 >= 0xc0, so the game never reaches past the table, but
the check's random inputs do. The table is the last object in the original's frame, so index 192..196 read
the pushed r4, r5, r6, r7, lr and 197 and up read the caller's frame. The C reproduces this: in range it reads
`v3[]`; beyond it reads `saved[]` (r4-r6 captured by an inline-asm `stmia` as the first statement, r7 and lr
from the clang frame record at `__builtin_frame_address(0)`) and then `entrySp[]` where
`entrySp = __builtin_frame_address(0) + 8` (the entry stack pointer under clang -O0 Thumb). These extra reads
only matter for inputs the game never passes.
