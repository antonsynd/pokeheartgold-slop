# ov115_0225F978 - gave up (sandbox artifact, same as ov112_021E6164)

The C in ov115_0225F978.c is a faithful reading of the asm: all 15 states, the work-struct offsets,
and the tail (render, then the 3D swap when state > 4). The check still cannot pass it.

The bounds check on the state uses `bl _0226021C`, a far branch to the function's own tail. On
hardware that is a plain goto, and the C does the same (`default` falls through to the tail). The
sandbox instead records it as a call to 0x0226021C, stubs it with a pseudo-random r0, and goes on into
the jump table with that r0. The original side then runs a case, or jumps outside the table when r0 is
over 14. The random state word is almost always over 14, so trial 0 already fails with "the number of
calls differs" (original 9, C 5).

I tried a scratch variant that called 0x0226021C and switched on its result. It still failed on the
same trial, because the stub's r0 was out of range and the original jumped through garbage table
entries. C cannot reproduce that, and calling into the middle of the function would be wrong on
hardware, so the faithful version stays.

Differences from the Platinum twin (EncounterEffect_EliteFourChampion) that this C follows:
- the gender test is `ov115_0225F968(fieldSystem)`;
- the class word at work+0x308 (0xCF or 0xD3) goes to ov115_02260254;
- `Sprite_SetPriority(sprite, 1)` replaces ov70_0223D8E8;
- `G2x_SetBlendAlpha_(0x04000050, 1, 0x1E, 0, 8)`;
- `ov01_021F1060` is called in place of ov59_0223C5B0;
- the window is removed with `RemoveWindow`;
- `REG_BLDCNT` is cleared directly at the end.
