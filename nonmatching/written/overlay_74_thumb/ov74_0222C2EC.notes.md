# ov74_0222C2EC: PASS

The MysteryGiftApp main state machine (59-entry jump table over `*state`; `bl _0222CD3A` is the far branch to the
common tail, so every state that does not return 1 early (53-55) ends at the tail: call the callback at
appData+0x29E8 if set, then ov74_022358C8(appData->animationStatus), return 0). Written from the asm with the
Platinum twin only as a guide to the callees; the appData fields are accessed by byte offset (0x5c8 state check,
0x15d8 state pointer, 0x29e8 callback, 0x29f4 animation status, 0x434/0x438/0x43c/0x440 timers and flags, 0x80 receive
status, 0x8c event data, 0xdc wonder card, 0xda bit 2 = has wonder card, 0x18/0x48/0x58 windows).

Points that mattered:
- `(flag << 0x1d) >> 0x1f` in the asm is a logical shift: the bit is extracted as `(flag >> 2) & 1`.
- State 50 calls ov74_0222ADBC(appMan, 0, 0, *state): r3 is the dispatch value, which the asm never reloads.
- The tail's `blx r1` is compared on r0-r3. r1 is the pointer; r3 is still the dispatch value (`ldr r3, [r5]`) when
  no call has happened since the dispatch, and a call clobbers it. `r3Left` models that: it starts as the state value
  for the states that can reach the tail without calling anything (default/unused states, > 0x3a, 15, 17-19, 21, 23,
  25, 35, 51, 56) and is cleared at the points where those states do call. r2 is passed as 0 (the leftover of the
  earlier calls); the callback only takes appData. The random trials do not reach the no-call paths, so that part is
  reasoned from the asm, not exercised.
- Reads of the shared globals (sWirelessDistribState at ov74_0223D0A8+0x10, gSystem.newKeys at +0x48) are done at the
  same points as in the asm (state 32 reads the distribution state twice).
