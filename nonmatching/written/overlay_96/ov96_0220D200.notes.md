# ov96_0220D200: PASS

The asm reads a 15-word table (narc member 5 of narc 0xaa, filled into sp+8) with three byte indices (r4[0], r4[3]+5,
r4[4]+10). The range check only logs (GF_AssertFail) and falls through, so a random index reads past the table: the
original's own saved r4-r7/lr, then the caller's frame.

The C reproduces those reads relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's
clang -O0 Thumb build): the table is at entry_sp - 0x50, words 15..17 are the caller's r4-r6 (read as the first
statements with `movs`), words 18/19 are r7/lr (same slots in clang's frame), the rest is the caller's frame. The first
local, `framePadding[15]`, keeps the C's own locals below the table (compiler-layout dependent, deterministic for the
check's flags). In-range behaviour is plain `table[idx]`.

Each index byte is re-read at its own step (after the preceding stores to *param_1), as the asm does, since the
pointer from ov96_021E60D8 may alias the output. The last step keeps only 8 bits of the middle field
(`lsl #0x18; lsr #6`), not 9.
