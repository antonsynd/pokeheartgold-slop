# ov96_021FA34C

Rewritten from the asm (the Ghidra draft was dropped). The function advances one item (`param_3`, a struct with a
float speed `unkC`, a float fraction `unk10`, a limit `unk50` and a step `unk54`), tracks a state in `unk28`
(0 -> 3 -> 4 on the `unk8 == 1` path, 1/2 on the other) and calls the sprite/sound helpers.

MWCC's float compare helpers `_fls` and `_fgr` return their result in the CPU flags and the asm branches on them
(`bhs` after `_fls`, `bls` after `_fgr`). The C wraps each in a small inline-asm function that does `bl _fls` /
`bl _fgr` and branches on the same flag test (lo / hi), so the exact ROM compare semantics (NaNs included) are kept.
The float adds, the `(s32)` cast, the `(float)` cast and the subtract use ordinary C operators, which clang lowers to
the ROM `_fadd`, `_ffix`, `_fflt`, `_fsub` helpers.

Details worth knowing: the constant stored to `unkC` is 1.0f (0x3f800000) in the `unk8 == 1` path and 0.5f (0x3f000000)
in the sound-trigger path; the two `unk4 + 0x200 <= 0` and `unk6 + 0x200 <= 0` guards compare a zero-extended u16
plus 0x200, so they never fire in the asm, and the C keeps them as written; `ov96_021FA83C` takes three arguments
(the asm sets r0, r1, r2; the callee overwrites r2 and never reads r3); `ov96_021FA340` is the 2-argument tail-call
thunk.
