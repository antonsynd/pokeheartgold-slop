# ov96_0220146C: PASS

Fills 16 entry pointers (`param_1 + 0x29c + 0x14*i`), calls `ov96_022014A4(entries, out)` (returns the count), draws `LCRandom()`, takes the remainder of `_s32_div_f(random, count)` (r1), and returns `out[(u8)rem]`.

The index is a byte, not bounded by the 16-word `out`. Reproduced as the asm reads it: relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's clang -O0 Thumb build), `out` begins at entry_sp-0x48, so index 16 is the saved r4, 17 the saved lr (both read as the function's first statements with inline asm), and 18..255 the caller's frame. For indices below 16 (all the game can produce, since rem < count <= 16) the C returns its own `out` array, which the callee fills. The check's stub for `ov96_022014A4` only writes `out[0]`; the rest is unwritten stack, read identically on both sides.
