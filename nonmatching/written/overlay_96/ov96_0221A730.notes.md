# ov96_0221A730: PASS

Three 4-byte arrays (table copy from ov96_0221D99C at sp+8, counters at sp+0xc, bytes at sp+0x10) sit in the
original's frame directly under its pushed r4-r7/lr. The table is read at `tbl[bytes[i] + counters[i]]` with
no bounds check, and `bytes[i]` is a byte taken through the pointer ov96_021E94EC returns, so a value above 3
reads on past the arrays. For in-range indices the C is exact. For larger ones OV96_0221A730_READ()
reproduces the original's read: offsets 12..31 from the table start are the saved r4, r5, r6 (inline asm at
entry), r7 and lr (from `__builtin_frame_address(0)`), and offsets from 32 up read the memory at the entry
stack pointer (`__builtin_frame_address(0) + 8`, valid for the check's clang -O0 Thumb build). The game never
takes that path. The `> 200.0` test is the original's double compare (_dfltu/_dgr), so the stored halfword is
clamped to 200.
