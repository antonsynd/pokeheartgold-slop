# ov96_0221918C: PASS

The asm zeroes a 30-word table at sp+0xc, passes it to ReadWholeNarcMemberByIdPair(0xaa, 9) and indexes it with four
bytes returned by ov96_021E60D8 (word offsets idx0, idx0+5, idx3+10, idx1+15, idx2+25 twice). The range check only logs
(GF_AssertFail) and falls through, so a random byte reads past the table: the original's saved r4-r7/lr, then the
caller's frame.

The C reproduces those reads relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's
clang -O0 Thumb build): the table is at entry_sp - 0x8c, words 30..32 are the caller's r4-r6 (read as the first
statements with `movs`), words 33/34 are r7/lr (same slots in clang's frame), the rest is the caller's frame. The
first local, `framePadding[32]`, keeps the C's own locals below the table (compiler-layout dependent, deterministic
for the check's flags). In-range behaviour is plain `table[idx]` (all zeros unless the narc read fills it).

Each index byte is re-read at its own step (after the preceding stores through the second pointer), as the asm does,
since the two pointers may alias. The float conversion is `(int)(0.5f +/- (float)(v << 12))` with 0.5 as the first
operand of _fadd, then a signed `/ 10` (_s32_div_f); the third field has no division.
