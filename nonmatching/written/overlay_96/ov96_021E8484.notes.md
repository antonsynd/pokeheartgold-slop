The order bytes (written by ov96_021E860C) are read through a pointer that advances once per participant with no
bounds check, so a count above 4 reads past the stack buffer: unwritten frame words, the saved registers and the
caller's frame. The C reproduces that: a helper uses the original's frame at its own addresses (entry stack pointer
minus 0x58), and ov96_021E8484 reserves 0x400 bytes of stack and forces clang to save r4-r6 (with r7 and lr) so they
sit where the original's saved registers are. Counts large enough to run past the cycle budget agree up to the budget.
