# ov96_02210C98: PASS

A six-state task function (state = `PokeathlonCourse_GetField1ED`, states above 5 return 0 through the asm's far `bl _02211626`): 0 creates the heap, VRAM/OAM setup and the work area; 1 builds sprite/object lists; 2 creates the object graph and copies the `ov96_0221D*` tables onto the stack; 3 queries 12 slots; 4 places the 12 sprites, builds the light vectors and starts the palette fade; 5 returns whether the fade finished.

The C mirrors the asm's 0x294-byte stack frame in a local struct (`STK(T, off)` is the asm's `[sp, #off]`), so the stack buffers the callees fill and the locals the asm reads back are the same bytes. Two accesses use an unchecked index and are reproduced relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's clang -O0 Thumb build, entry_sp-0x2a8 being the asm's sp): the table at sp+0x9c read with `ov96_021E6138`'s result (inside the frame it is the mirrored slot, outside it the same absolute address), and the halfword pairs written at sp+0xb4 + 4*remainder (`_s32_div_f`'s remainder, which the check answers with a random value). In the game the index is within the table and the remainder is 0..2, so those paths are exact for in-game inputs. Tables `ov96_0221D*` are referenced as externs.
