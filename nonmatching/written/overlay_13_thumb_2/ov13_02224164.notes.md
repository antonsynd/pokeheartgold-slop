# ov13_02224164

PASS, with one oddity. The asm terminates its two on-stack 0x22-byte name buffers with
`buf[entry->nameLen] = 0` and nameLen (read from the list) is never bounds-checked. With real data it
is <= 0x20, but the check feeds ROM bytes, so nameLen is often huge (0xFFFFFFxx) and the store lands on
the function's own stack slots (idx, flags, counters), which then changes control flow.

To reproduce that exactly, the C keeps the asm's memory-resident locals in a struct whose layout is the
asm's frame (a, b, out, idx, cnt, bFlag, aFlag, result, found, bssidA, name2[0x22], name[0x22]; 0x6c bytes)
and StoreNul() writes either into that struct (offset inside the frame) or at the absolute address
entrySp - 0x80 + off (entrySp = frame address + 8 under the Thumb prologue). The real game never
passes nameLen > 0x20, so a clean rewrite would use plain buffers and `name[len] = 0`.
