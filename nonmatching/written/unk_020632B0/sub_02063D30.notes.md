# sub_02063D30: PASS

The asm copies the eight ROM words at 0x020FE0E4 to sp+0 and indexes the copy with the signed bytes unk_05 (row, *16)
and unk_06 (column, *4) of the state struct, unchecked (the assert on the search result only logs). A random byte
therefore reads the original's own frame: its stack copy, the registers it pushed, the caller's frame, or memory
below its sp.

The C reproduces those reads relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's
clang -O0 Thumb build). asm_sp = entry_sp - 0x38 (push {r3-r7, lr}, then 0x20 bytes): +0x00..0x1f is the ROM table
(read straight from the ROM words), +0x20..0x2f the caller's r3-r6, +0x30/0x34 r7/lr (same slots in clang's frame),
above that the caller's frame, below it memory the asm never wrote. The first local `framePadding[0xA80]` keeps
this C's own locals (and the clang prologue's frame) out of the 2.5 KB below asm_sp that rows -128..-1 can reach.
This is compiler-layout dependent but deterministic for the check's flags; in-range behaviour is the plain table
lookup.

The caller's r3-r5 are read with `movs` as the first statements. The large frame makes clang's prologue use r6 as
scratch, so the caller's r6 is read from the slot the prologue pushed it to (just below the saved r7). A random
check does not hit the r6 slot (it needs row*16 + col*4 == 0x2c), so that read is reasoned, not exercised.
