# ov113_021E5A7C

`ov113_021E5A48(pokedex, buf)` fills a 4-byte stack buffer and returns how many entries it wrote (at most 2
in the game: Unown forms `!` and `?`). The asm then copies `n` bytes starting at `sp` into `data->unk3A[]`.
The check's stub returns any u8, so for `n > 4` the original reads past the buffer: first the prologue's
pushed r3, r4, r5, r6, lr (sp+4..sp+23), then the caller's frame (entry sp + k).

The C keeps the exact behaviour for in-range inputs (n <= 4 reads `buf`) and reproduces the out-of-range
reads relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under clang -O0 Thumb):
the entry r3-r6/lr are captured by one inline-asm `stmia` as the first statement, and bytes 24 and above
come from `entrySp[i - 24]`. These extra reads only matter for the check's random stub results.
