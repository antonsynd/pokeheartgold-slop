# sub_02057524: PASS

Copies the 5-word table at 0x020FC7B8 (`_020FC7B8`: 2, 4, 8, 0x10, 2) into a stack array and returns entry `idx` (signed compare, `GF_AssertFail` when `idx >= 5`; the index is NOT clamped after the assert).

The index is unchecked, so the asm reads past its table. Reproduced relative to the entry stack pointer (`__builtin_frame_address(0) + 8` under the check's clang -O0 Thumb build, `push {r7, lr}`): the asm frame from entry_sp-0x20 is table[0..4], then the saved r3 (table[5]), the saved r4, the saved lr, then the caller's frame; negative indices read the free stack below. The C returns the ROM table for 0..4, r3/r4/lr as received (read with inline asm as the first statements) for 5..7, and otherwise reads memory at entry_sp-0x20+4*idx. The C keeps no frame array and only a few scalar locals so that its own frame (about 24 bytes) stays above the region the asm reads for negative indices. For in-range inputs (the game only passes 0..4) the C is exact.
