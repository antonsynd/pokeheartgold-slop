# unk_0201010C part 01

All 30 functions (FadeFunc_00 to FadeFunc_29) pass check.py (2000 trials each). They are the Platinum screen_fade_funcs.c twins; the asm fixed the data and the order.

- Every function takes the `FadeWork` record (same layout as src/nonmatching/unk_0200FA24.c: +0x0C phase, +0x24 colour `u16`, +0x28 and +0x2C `int` state words). Phase 0 sets the background colour (`sub_0200FCDC`), hands a data table to the effect starter, stores the two state words and returns 0; any other phase returns the effect's update function.
- The state words are (1, 1) / (0, 1) for FadeFunc_00 / 01 (brightness fades, which call `sub_02010B14(work, 1 or 0)` and `sub_02010BB4`), and (1 or 0, 0) for all window fades: out fades store 1 first, in fades 0.
- The Platinum twin's table order does not always match: HeartGold's FadeFunc_22 is Platinum's FadeFunc_23, FadeFunc_23 and FadeFunc_24 use the swapped rectangle order, and FadeFunc_22 has no twin line in twin.py. The asm labels decide.
- Tables are defined in the C under their asm labels (`_020F5D58` ... `_020F5F1C` in rodata, `_0210F64C` ... `_0210F694` in data); the gate confirmed every byte against the ROM. The data ones are the eight `{ptr, u16 count, u16 flag}` statics (`ptr` is filled in at run time by FadeFunc_02, 03, 04, 05, 08, 09, 10, 11); the asm addresses them as `_0210F64C + offset`, which is how the compiler placed the statics of this file, so they are separate objects here. `_0210F664` and `_0210F67C` (the same kind of record) belong to functions outside this part.
- The rodata blocks are bigger than what these functions use in a few places (for example `_020F5D68` and `_020F5D80` continue with 16 and 8 bytes of other tables); only the leading bytes the functions use are defined here.
- Record shapes: window rectangle pairs are `{u8 x1, y1, x2, y2}` x 2 followed by four bytes (0, 0x3F, GX_BLEND_PLANEMASK_BD or swapped, 0/1); the 0200FB7C family is four `u16` plus the same four bytes; the 0200FC2C family is two `u16` angles (0x3FFF = 90 degrees) plus four bytes; FadeFunc_28 and 29 build a 16 byte descriptor on the stack (two rectangle array pointers, `u16` 4, `u16` 0, `u8` 0x3F, `u8` 0x20, `u16` direction).
- Callee prototypes (`sub_0201289C`, `sub_0201164C`, ...) are declared locally from how the asm calls them.
