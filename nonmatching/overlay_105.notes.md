# overlay_105

- All the rodata and data of the overlay (ov105_021E5DC4 .. ov105_021E5EA4) is declared `extern`; none is defined in the C. Some of it is passed by address to other functions (ov105_021E5DE0 to G3X_SetEdgeColorTable), and a second copy in the C would sit at a different address and fail the call comparison. `_021E5DC4` and `_021E5E80` are unnamed labels in the asm and keep those names.
- The gate compares only the first four arguments of each call and never looks at the stack frame, so the stack-passed arguments (BeginNormalPaletteFade args 5 to 7, Camera_Init_FromTargetDistanceAndAngle args 5 to 7, NNS_G3dGlbPolygonAttr args 5 and 6) and the copied-in constant tables were checked against the asm by hand only.
- The struct behind `args->unk4` (light vectors, light colours, diffuse/ambient/specular/emission, two flags, polygon attributes, 0x48 bytes) is the fork's `ModelAttributes`; the order of the NNS_G3dGlb* calls matches `ModelAttributes_ApplyGlobal`, which the asm inlines as a loop instead of calling.
- ov105_021E5E2C is an array of `CameraParam` (0x14 bytes: distance, CameraAngle, perspectiveType, perspective), ov105_021E5DF0 an array of VecFx32 and ov105_021E5DCC an array of `{u16 near, u16 far}`. The asm indexes each one as `base + type * stride + frame * stride` with the same stride for both, and each table has only 2 entries, so they are declared `[2][1]` and indexed `[type][frame]`. The two entries of each table are identical, and `frame` (unk9f) is 0 whenever ov105_021E5BCC runs in practice (the overlay ends after one pass), so the shape is a guess that cannot be told apart from the data.
- UnkStruct_ov105_021E5900 is 0xA8 bytes; the 0x7C-byte model slot at +4 is indexed by unk9f in ov105_021E59DC (`models[1]`) and is `models[0]` elsewhere. Offsets +0x80 (NNSFndAllocator), +0x90 (camera target), +0x9C..+0xA1 (bytes) and +0xA4 (sound effect table pointer) were checked with static asserts in a scratch copy.
- The four `NNSi_G3dModifyMatFlag` calls in ov105_021E5CA4 (flags 0x40, 0x80, 0x200, 0x400) are the fork's `NNS_G3dMdlUseGlbDiff/Amb/Spec/Emi` inline wrappers, in that order; the wrappers compile to local calls here, and the gate sees the same NNSi_ calls.
- The 0x1E-frame sound-effect trigger in ov105_021E59DC reads `unkA4[unk9f]` after unk9f was possibly incremented in the same call, as in the asm.
