# overlay_07 part 12

- This part is the battle animation helper block (Platinum's battle_anim_helpers.c): a VBlank DMA controller (0x1C bytes: two tasks, doDMA at +8, swapBuffers at +0xC, two callbacks, one parameter), a per scanline scroll context built on it (ov07_02222BE4: controller, double buffer manager at +0x1C, two buffers of 192 words at +0x20 and +0x320, register address at +0x620, size 0x624) and a sine scroll context (ov07_02222CCC: controller plus the screen scroll manager at +0x1C, size 0x20), the palette fade task (0x1C bytes) and two lookup functions.
- The twin tool's pairing is shifted for ov07_02222D90 to ov07_02222DE4 (it names the wrong Platinum function for several); the asm decides: D90 maps a background number 0 to 3 to the BGxHOFS register address (anything else is returned unchanged), DC8 is the x/y mean, DE4 the distance (FX_Sqrt) and E0C the angle (FX_Atan2Idx), and 0x7FFF is the constant there (Platinum has 180 degrees).
- ov07_02222F7C is the grayscale conversion, 76*R + 151*G + 29*B >> 8 with R in the low 5 bits. The sandbox's write log holds 65536 byte entries and counts the stack bytes the decompiled function writes too, so a count above 32768 colours only compares equal when the C writes exactly as many distinct stack bytes as the original's `push {r4-r7}` (16). The locals are kept to that on purpose (a0, a1, i, one colour halfword, one word).
- ov07_02222BE4 is defined last in the file on purpose. The gate's stub allocator can return a block ending inside the first bytes of the linked blob, and the 0x624 byte memset then wipes the function pointers in the decompiled function's literal pool; at the end of the file that cannot happen.
- ov07_02236520 (84 entries) and ov07_0223649C (33 entries) are only declared; their contents are the ROM's.
