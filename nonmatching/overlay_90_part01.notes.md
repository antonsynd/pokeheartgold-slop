# overlay_90 part 01

- This part is the start of the Wi-Fi lobby minigame overlay (Platinum's ov114_0225C700): the member table (ov90_02258800 builds a 0x10 byte structure: save data at +0, up to four member ids at +4, member count at +8, own index at +9, two flags at +0xA and +0xB, the shared lobby block at +0xC), the two view teardown functions (ov90_02258938, ov90_02258A04), the icon helper (ov90_02258BD4 to ov90_02258CE0) and the fixed point setup in ov90_02258CF0 (FX_Mul and FX_Div as in Platinum).
- The twin tool names a few HeartGold calls wrongly: ov90_02258938 and ov90_02258A04 call ov90_022591D4 (not ov18_021E6280), and ov90_02258A04 clears the two blend registers with G2_BlendNone and G2S_BlendNone.
- ov90_022588A4 compares a byte against 0xFFFFFFFF, which is never true; the C keeps the comparison on a u32.
- ov90_02258AA8 (ranking of up to four scores, insertion sort held in a 4 byte stack array) does not pass check.py and cannot: the gate also feeds counts above 4 (for example 0x87), and then both the original and the C write past the 4 byte array into the stack above the frame and clobber their own locals in different ways. For counts 0 to 4 the C agrees on all 2000 trials; this was checked with a scratch copy of the gate in which the second argument is reduced modulo 5 (`NUG_LIMIT_ARG1=1`, the real tools untouched). Four members is the game's limit, so the C is right for every valid input.
