# unk_020632B0 part 03

All 30 functions of the part pass (sub_020643B8 to sub_02064824), 2000 trials each (sub_02064520 had 770 and sub_02064468 8 inconclusive trials, the rest agreed). Platinum's trainer_encounter.c twins fit all but the arguments: the twin renaming in twin.py is unreliable here (it maps several HeartGold names to unrelated Platinum names), so the calls were taken from the asm.

- The data of the approaching-trainer task is a 0x30-byte block from `Heap_AllocAtEnd(HEAP_ID_FIELD1, 0x30)`: +0 state, +4 done flag (read by sub_0206460C), +8 direction (-1 means unset), +0xC sight range, +0x10 an unused argument, +0x14 approach type (2 is the double battle case), +0x18 approach count, +0x1C delay counter, +0x20 animation handle (from ov01_02200540, passed to ov01_022003F4 and sub_02068B48), +0x24 trainer map object, +0x28 player avatar, +0x2C field system.
- The dispatcher sub_02064630 runs `_020FE1A4[state](data)` until the state function returns something other than 1. `_020FE1A4` has 18 entries (sub_0206464C ... sub_020648E4); the last three live in the next part and are declared extern. It is defined here and passes the gate's data check against the ROM. check.py compares the argument registers of an indirect call as if it took four arguments, and the original leaves r2 and r3 untouched, so the C is written as `func = table[state]; while (func(work) == 1)` (clang then does not touch r2 and r3); the shorter form `while (table[state](work) == 1)` makes clang use r2 for the scaled index and fails with "a call differs".
- ov01_02200540 is called with three arguments (r3 is not set), not the four of Platinum's twin; the fork's header agrees.
- include/unk_020632B0.h declares sub_02064598 as `BOOL (void)`, sub_020645AC as `void (int)` and sub_0206457C as returning `int` with a `u16` last parameter. The asm takes the SysTask * in r0 for the first two and passes four stack arguments straight through the third, so this file does not include that header and declares the real types itself.
- sub_02064694 switches on movement types 0x33 to 0x36 (a four-entry jump table in the asm); the fork has no names for them.
