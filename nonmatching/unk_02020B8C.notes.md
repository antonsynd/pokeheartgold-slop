# unk_02020B8C

- sub_02020F4C: the logic agrees with the original on every trial except the uninitialised reads of `intPartX` and `intPartY`. The sandbox does not run `FX_Modf`, so both are read from shared pseudo-random fill by address. The original keeps them at TOP-0x18 and TOP-0x1c, where clang -O0 places the spill slots of the parameters `c` and `d`, so the decomp side reads its own saved pointers there instead. The remaining failing trials are those where `out` is NULL (the original writes through it unconditionally, as the C does) or the intersection test reads those two values.
- GetDistanceFromPointToLine and CalcAngleBetweenVecs read `VecFx32` locals that the stubbed `VEC_Subtract`/`VEC_Normalize` never fill, so their locals are declared in the order that puts them at the original's stack addresses under clang -O0 (first declared sits highest, directly under the spilled parameters). Changing the declaration order makes them fail.
