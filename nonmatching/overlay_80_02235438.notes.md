# overlay_80_02235438

- FrtCmd_138: the C passes `ov80_0223573C` to `FrontierScriptContext_Pause`, as the asm does (`ldr r1, =ov80_0223573C`). check.py reports a call mismatch only because arm_link.py resolves a function-pointer relocation (R_ARM_ABS32) to the copy of the function placed in the sandbox blob (0x02380000 and up), not to the game's address 0x0223573D. Only direct calls (BL) are redirected to the game's addresses. With the pointer replaced by the literal 0x0223573D in a scratch copy, FrtCmd_138 passes 500/500 trials, so nothing else differs. The file keeps the function reference.
- `FrontierFieldSystem` (include/scrcmd_9.h) hides two fields inside `filler8CA`: a u32 at 0x8CC (battle result, written by FrtCmd_136) and a `BattleSetup *` at 0x8D0 (written by FrtCmd_135, read and deleted by FrtCmd_136). They are reached through the local `UnkStruct_Ov80_02235438` overlay. Taking `&data->filler8CA[6]` and casting to a pointer makes clang assume 2-byte alignment and emit two halfword accesses, which differ from the original word access when the sandbox hands in an unaligned `data`.
- The first definition found for a name wins in verify_all.py, and src/nonmatching comes first, so this file shadows src/frontier/overlay_80_02235438.c.
