# overlay_41_02248ED4 part 02

- ov41_022499B4 fails check.py on trial 0 ("memory differs") although the C is equal to the asm. The function calls `memset(ptr, 0, count << 4)` with a random 32-bit `count`, so the harness memset helper writes its 0x10000-byte cap. The harness write log holds only 65536 distinct bytes (MAX_WRITES in sandbox.c) and the stack writes of the function count against it: the original (push of 4 registers, 16 bytes) leaves room for 65516 memset bytes, the clang -O0 build (push of 2 registers plus 3 spilled arguments) for 65512, so the last few zeroed bytes are logged on one side only and compare as different. A scratch copy with the parameter narrowed to `u8 count` (so the size stays below the cap) passes all 500 trials. The real callers pass 0x15 and 0x2CF, so a `u8` would be wrong and the C keeps `int count`.
- ov41_022497A8 and ov41_02249820 read `picX/picY/width/height` after calls (ov41_02249780, ov41_022497A0) that the harness answers without writing the out-parameters, so the values come from the harness's address-seeded fill of the stack. They only agree when the locals sit at the same absolute stack addresses as in the asm frame (y at sp+0, x at sp+4, height at sp+8, width at sp+0xC under the 0x18-byte push). The declaration order (width, height, picX, picY, then the result) and the single `return result` are what makes clang -O0 place them there (no return-value slot above them); reordering them makes the gate report a false call difference.
- The struct behind `a0` of ov41_02249780..ov41_02249888 is only partly known: a Pokepic pointer at +0, a TouchscreenHitbox at +4 (ov41_02249768 and ov41_02249774 tail-call TouchscreenHitbox_TouchHeldIsIn / TouchscreenHitbox_PointIsIn with `a0 + 4`) and the four bytes at +8 that ov41_02249888 copies out.
- ov41_0224989C and ov41_022498E8 scan an 80 by 80 4-bit bitmap (`data[index / 2]`, nibble `index % 2`, index `i + j * stride`) for the first opaque row and the opaque bounding box; the odd `0xF << ((index % 2) * 4)` mask is what the asm computes (including the signed remainder idiom).
- ov41_022499B4, ov41_022499DC and ov41_022499F0 manage an array of 0x10-byte nodes (`{obj, type, next, prev}` in src/overlay_41_02248400.c) with a count at +4.
