# overlay_49_02258800, part 2

ov49_02258DAC .. ov49_02259294. All thirty came from Platinum twins (overlay070 ov70_0225CCAC .. ov70_0225D194) and passed after renaming.

- `UnkOv49Ctx` (the owner struct): +0x00 `UnkStruct_ov42_022280A8 *`, +0x04 an ov45 manager, +0x08 array of `UnkOv49Entity` (0x28 each), +0x0C u16 count, +0x10 and +0x14 pointers (+0x14 is the map handle given to ov49_022589AC / ov49_022589C4 / ov49_022589D8), +0x20 and +0x24 entity pointers (ov49_02258DAC / ov49_02258DB0; +0x24 is set in ov49_022591D8 for the entry with id 0x61). It is also what ov49_022593C0 takes as its pool.
- `UnkOv49Entity` (0x28 bytes): +0x00 `UnkStruct_ov42_02228110 *`, +0x04 ov45 object, +0x08 u16, +0x0A u8 (busy flag), +0x0B u8 (behaviour kind, index into the two tables), +0x0C 0x18 bytes of per-behaviour state, +0x24 current behaviour function.
- Tables defined here: ov49_02269654 (direction order 3,2,1,0), ov49_02269678 (four 8-byte spawn entries: id, byte, u16, byte, 3 pad), ov49_02269698 (ten exit callbacks: nine NULL then ov49_022599F8), ov49_022696C0 (ten behaviour functions). All four match the ROM bytes under the gate.
- The 4-byte `UnkStruct_ov44_02232914` is passed and returned by value; the asm spills it to the stack, which the AAPCS handling of the gate treats the same as clang's register passing.
- ov49_02258EEC clears the 0x18-byte state with a byte loop (the original inlines it). With `memset` the gate failed one trial because the random entity pointer fell inside the gate's own linked blob and the memset stub and the inlined loop clobbered it differently; the loop is identical in effect and passes.
- ov49_02259294 (random pick from a byte table) is the same function Platinum has; the unsigned remainder comes from `_u32_div_f`.
