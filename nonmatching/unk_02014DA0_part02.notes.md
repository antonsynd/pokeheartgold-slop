# unk_02014DA0 part 2

All 30 functions PASS (2000 of 2000 trials each); 10 of them were seeded by a Platinum twin, and the tree's earlier src/unk_02014DA0.c was checked against the asm and corrected.

- include/unk_02014DA0.h is not included: its prototypes use `SPLEmitter *` for the particle system handle and declare `sub_02015460` as `void`. The asm returns the number of live systems in r0, so it is `int`. `sub_020154B0` returns the count of active emitters (`manager->act_emtr_list.node_num`), `int`, not `BOOL`.
- The particle system handle (the thing sub_02014DB4 allocates, 0xDC bytes) is a local `ParticleSystem`, laid out as in Platinum: manager +0, resource +4, lastAddedEmitter +8, heapStart +0xC, heapCur +0x10, heapEnd +0x14, texAlloc +0x18, palAlloc +0x1C, camera +0x20, cameraFov +0x30, cameraPos +0x34, cameraUp +0x40, cameraTarget +0x4C, texture keys +0x58, palette keys +0x98, flags +0xD8, id +0xDA, cameraProjection +0xDB.
- The arguments of sub_02015538 and sub_02015550 and everything after it are the library `SPLEmitter` itself (axis at +0x50, `p_res` at +0x20), not the system handle. The existing C read the axis from the system at the wrong offset.
- `sub_02015550` looks a field up in the resource's `fld_ary` by the `spl_calc_*` function it runs: 0 gravity, 1 random, 2 magnet, 3 spin, 4 scfield, 5 convergence. Callers: gravity magnitude (VecFx16 at +0), magnet target (VecFx32 +0) and force (s16 +0xC), spin angle (u16 +0) and rate (u16 +2), convergence target (+0) and force (s16 +0xC). The getters write 0 when the field is absent; the earlier C of sub_020154C4 passed NULL instead of the emitter to SPL_Delete.
- `_021D10A0` (bss) is `{ loadingSystem, emitterCallbackParam }`; `_021D10A8` is the 16-entry system table. Both are `extern`, since they are the game's globals. `_020F6078` is the default camera up vector (0, 0x1000, 0), not 0x100000 as the earlier C had it; `_020F60DC` is the cursor glyph string { 0x011F, 0xFFFF }. Both are defined in the C and match the ROM bytes.
- `ListMenuCursorNew` fills `struct ListMenuCursor { u32 color; String *text; }` (color 0x0001020F is MAKE_TEXT_COLOR(1, 2, 15)).
- Twin caveat: twin.py paired sub_02015504, sub_02015510, sub_02015538 and the "Set" twins of sub_02015640/sub_02015720 by name order only; the asm for those is the opposite direction (getters) or a different field, so they were written from the asm.
- Tool quirk: verify_all.py's definition finder skips a function whose parameter list contains a function-pointer declarator (`void (*cb)(...)`), so sub_02015494 only counted after the callback type became the typedef `SPLEmitterCallback`.
