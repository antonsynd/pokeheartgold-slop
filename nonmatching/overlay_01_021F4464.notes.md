# overlay_01_021F4464

Display capture (DISPCAPCNT) setup. The shared headers have no struct for this, so the file defines
`UnkStruct_ov01_021F4464_Config` (0x2c bytes, the template ov01_02206B94 in overlay_01_021F467C) and
`UnkStruct_ov01_021F4464` (0x38 bytes, the SysTask environment).

Findings:

- Config +0x28 is the heap id passed to CreateSysTaskAndEnvironment (priority is the constant 5), not a task priority.
- Config +0x00 is a GXDispMode compared signed (2, 6, 10, 14 select VRAM-A..D), so it is declared `int`.
- GX_GetBankForLCDC has no prototype in lib/include; declared locally.
- Environment layout: +0x00 saved LCDC bank, +0x04 config copy, +0x30 ready flag (set by the VBlank task
  ov01_021F4584), +0x34 the SysTask.
- ov01_021F4464 copies the config in 2-word blocks (ldmia/stmia) then one word. It is written as an explicit
  pair loop instead of a struct assignment because the sandbox calls it with config and environment both
  NULL (overlapping), where a byte-wise memcpy and the block copy give different bytes.

Gate results: all five functions PASS with the current tools. (Before the 20:18 change to arm_link.py, which makes a data
reference to a function the file defines resolve to the game's address, ov01_021F4464 failed because the callbacks
`ov01_021F4544` / `ov01_021F4584` passed to CreateSysTaskAndEnvironment / SysTask_CreateOnVWaitQueue pointed into the
placed copy; it had been proven on a scratch copy with the siblings left undefined.)
